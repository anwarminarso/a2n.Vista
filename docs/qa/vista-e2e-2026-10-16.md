## Gaps left in place

The skipped test is the round trip the live host should provide (list 200, create 200 with a key and an `ETag`, detail, update with `If-Match`, delete with `If-Match`, detail 404). It was not executed. Two separate gaps keep it skipped:

1. Shipped `northwind.db` has no `VistaMemos` table. The sample's own `Program.cs` says the write self-test uses an isolated in-memory database because of that. On the live host, list / update / delete surface as 500 (`no such table`; `VistaExceptionHandlingMiddleware` does not map `SqliteException`), and create surfaces as 409 `write-conflict` because `EfViewExecutor.SaveWriteChangesAsync` classifies a non-concurrency `DbUpdateException` as `VistaWriteConflictException`.
2. Even after a row can be stored, `HandleCreateAsync` returns `200` with `VistaWriteResponse` (the key only) and does not copy `IWriteTokenSink.PostWriteToken` onto an `ETag`. `UpdateOk` does that for update. `MemoRow` is `MemoId`, `Subject`, `Body` — no `RowVersion` — so a detail response does not carry the token either. Update and delete on this view require `If-Match` (missing header is 428). The in-memory self-test reads `RowVersion` from the `DbContext`, which an HTTP client cannot do. The skipped test asserts a non-null `ETag` on create so this stays visible when the test is unskipped.

No other product failure showed up in the 28 passing tests. An earlier attempt of this same suite failed `View_Browser_Paging_Changes_The_First_Row` because Playwright treats an `<option>` as hidden; the wait was changed to `Attached`. That was a test bug, and the run above is the one that passed.
